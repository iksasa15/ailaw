# مواصفات «كلام المحامي ← لغة الإشارة» في المنصة

التاريخ: 2026-10-10 · الفرع: `web-speech-to-sign` · النطاق: الموقع (`web/`) فقط، لا تطبيق الآيفون.

## 1. الهدف

حين يتكلم المحامي في جلسة المنصة يتحوّل كلامه إلى لغة إشارة **يفهمها الأصم**: لوحة مترجم كبيرة
تعرض الإشارات جملةً جملة، وتحتها النص كاملاً، بلا تكرار ولا قطع، على الشاشة التي أمام الأصم.

### ما قاله المستخدم
- الميزة في المنصة وليست في التطبيق.
- الكلمة التي لا إشارة لها: **هجين** — فيديو إن وُجد، تهجئة للقصيرة، وبطاقة مكتوبة للباقي.
- مكان العرض: **الاثنين** — لوحة كبيرة في جلسة اللابتوب، وتملأ الجوال المرتبط بالـQR عند الأصم.
- النهج: محرك ترجمة داخل المتصفح (بلا خادم ولا ذكاء اصطناعي).
- الجزء الأول (المحرك) والجزء الثاني (العرض والتدفق) معتمدان كما عُرضا.

### الوضع الحالي (سبب العمل)
- `resolveSignClips` في `web/src/data/signLexicon.js` يعرف 10 جمل السيناريو فقط؛ أي كلام آخر يُتهجّى
  حرفاً حرفاً (0.9 ث للحرف، حتى 48 حرفاً) — جملة من 10 كلمات ≈ 35 ث. فيديوهات الكلمات العشرين
  (`word-*.mp4`) لا تُستعمل كلمةً كلمة.
- `Home.jsx` يأخذ آخر 12 كلمة من النص المتراكم كل 800ms فيُعاد ترجمة الكلام نفسه، وكل مقطع جديد يقطع ما قبله.
- المترجم مربع صغير (`SignCoachAvatar`، عرضه 9.5rem) يدور في حلقة على العبارة نفسها.
- الفيديوهات مولّدة بالذكاء الاصطناعي (انظر `public/signs/videos/README.md`)، فيجب أن يكون استبدالها
  بتسجيلات مترجم حقيقي سهلاً.

### معيار النجاح
1. جلسة لابتوب بلا جوال: يقول المحامي (أو يكتب بوضع «المحامي») «السلام عليكم، أنا محاميك» ← تُعرض
   فيديوهات جملة السيناريو في اللوحة الكبيرة، والنص تحتها والكلمة الحالية مميّزة.
2. «نحتاج الأوراق يوم الأحد» ← «نحتاج» بطاقة مكتوبة (5 حروف، لا فيديو لها)، ثم إشارة «ورق»، ثم «يوم»
   و«احد» تهجئةً.
3. كلام متواصل: كل جملة تُترجم **مرة واحدة**، بالترتيب، دون قطع؛ يظهر «+N بانتظار»؛ إن تجاوز
   الانتظار 3 جمل يقفز للأحدث. كل الجمل تبقى في المحادثة والمحضر مرة واحدة.
4. جوال مرتبط بالـQR (الأصم): ما يقوله المحامي على اللابتوب يظهر في مترجم يملأ أعلى شاشة الجوال.
5. الاختبارات الآلية خضراء، البناء ينجح، ولا أخطاء في الـconsole.

## 2. خارج النطاق
إعادة صياغة الكلام بالذكاء الاصطناعي لقواعد لغة الإشارة، تصوير فيديوهات إشارة جديدة، شخصية ثلاثية الأبعاد،
تغيير ترجمة إشارات الأصم إلى صوت (موجودة)، تطبيق الآيفون، الخادم (`backend/`) — لا تغيير عليه.

## 3. محرك الترجمة

### الملفات
- `web/src/data/signVocabulary.js` — القاموس: مصفوفة مداخل `{ clip, label, words }`.
  - `clip`: اسم ملف تحت `/signs/videos/` بلا امتداد (مثل `word-paper`).
  - `label`: ما يُكتب تحت الفيديو.
  - `words`: الكلمات والعبارات (كلمة إلى 3 كلمات) التي تُعرض بهذه الإشارة، مكتوبة طبيعياً.
  - **إضافة إشارة لاحقاً = وضع الفيديو في المجلد + سطر واحد هنا.**
- `web/src/platform/signTranslate.js` — المحرك (دالة صافية، بلا React).

### الواجهة
```js
translateToSigns(text) → { tokens: string[], steps: Step[] }
// tokens: كلمات النص الأصلي كما قيلت (للعرض والتمييز)
// Step = { kind: 'video', src, label, token }      فيديو إشارة
//      | { kind: 'letter', src, label, token }     صورة حرف (تهجئة)
//      | { kind: 'word', label, token }            بطاقة مكتوبة
// token: فهرس الكلمة في tokens التي تخصّها الخطوة (لتمييزها في النص)، أو null لجملة كاملة
```

### القواعد بالترتيب
1. **جملة سيناريو**: إن طابق النص (بعد التطبيع) إحدى جمل `LAWYER_PHRASES` العشر أو احتواها كاملة ←
   خطوات `LAWYER_SIGN_CLIPS` لتلك الجملة (`token: null`).
2. **غير ذلك، كلمةً كلمة** بترتيب الكلام:
   - **تطبيع للبحث فقط**: حذف التشكيل والتطويل؛ `أ إ آ ٱ ← ا`، `ة ← ه`، `ى ← ي`؛ حذف علامات الترقيم.
   - **مطابقة الأطول أولاً**: نافذة 3 ثم 2 ثم 1 كلمة مقابل `words` في القاموس.
   - لكل كلمة تُجرَّب الصيغ: كما هي، ثم بحذف سابقة واحدة من (`وال بال فال كال لل ال و ف ب ل ك`)،
     ثم بحذف لاحقة واحدة من (`كم هم ها ك ه ي`)، والاثنان معاً. إن انتهى الجذر بعد حذف اللاحقة بـ`ت`
     تُجرَّب أيضاً بـ`ه` (قضيتك ← قضيه).
   - **حروف الربط** تُتخطّى في الإشارات وتبقى في النص: `في من على الى عن ان او ثم قد لقد هذا هذه ذلك
     تلك الذي التي يا مع و`.
   - **كلمة معروفة** ← خطوة `video`.
   - **كلمة غير معروفة طولها ≤ 4 حروف** (بعد حذف `ال` من أولها) ← خطوات `letter` لكل حرف
     (من `LETTER_SIGN_CLIPS`، مع `لا` حرفاً واحداً).
   - **كلمة غير معروفة أطول، أو رقم** ← خطوة `word` واحدة بالكلمة كما قيلت.
3. نص فارغ أو لا يبقى منه شيء ← `steps: []`.

### التوافق
`resolveSignClips` يبقى بتوقيعه ويستعمل المحرك للنص الحر، فتستفيد العدسة القديمة (`SignCoachAvatar`)

يبقى تهجئة كاملة كما هو.

## 4. الكلام المتواصل

- `useBrowserStt` و`useSttSocket` يكشفان إضافةً إلى `text` المتراكم: `final: { id, text } | null` —
  آخر مقطع نهائي، و`id` يزيد مع كل مقطع.
- `web/src/platform/speechBuffer.js`: `createSpeechBuffer({ pauseMs = 800, onSentence })` يعيد
  `{ push(text), flush(), cancel() }`. يجمع المقاطع المتتالية، وبعد سكون `pauseMs` يستدعي
  `onSentence(text)` مرة واحدة بالنص المجمَّع ثم يفرغ.
- `Home.jsx` يغذّي المخزن من `stt.final` (كل `id` مرة واحدة) بدلاً من «آخر 12 كلمة»، وكل جملة
  ناتجة تمر بالمسار الحالي نفسه: `setLocalLawyerPhrase` + `emitConversation('lawyer', …)` + النشر للغرفة
  حين تكون الشاشة شاشة المحامي.

## 5. طابور العرض

`web/src/platform/signQueue.js` (دوال صافية):
```js
initialQueue → { items: [], current: -1, step: 0 }
enqueue(state, { id, text })   // يترجم بالمحرك؛ يتجاهل id مكرراً؛ يتخطّى الجمل بلا خطوات
advance(state)                 // الخطوة التالية، ثم الجملة التالية؛ يقف بعد آخرها
skipToLatest(state)            // يقفز لأحدث جملة من خطوتها الأولى
replay(state)                  // يعيد الجملة الحالية من أولها
pending(state) → number        // عدد الجمل بعد الحالية
```
- `MAX_PENDING = 3`: إن تجاوز الانتظار 3 بعد `enqueue` ← `skipToLatest`.
- الجملة الجديدة لا تقطع الحالية.
- مدد الخطوات: حرف 800ms، بطاقة مكتوبة 1200ms، فيديو حتى `ended` (أو 4000ms إن لم يصل `ended`
  أو فشل التحميل)، وفاصل 400ms بين الجمل.

## 6. لوحة المترجم

`web/src/components/platform/SignTranslator.jsx`:
```jsx
<SignTranslator
  sentences={[{ id, text }]}     // جمل المحامي بالترتيب
  status={{ state, partial, error, onRetry }}   // اختياري: حالة الاستماع على هذا الجهاز
  compact={false}                // تخطيط الجوال
/>
```
- مسرح كبير: فيديو الإشارة، أو صورة الحرف على أبيض، أو بطاقة الكلمة بخط كبير. تحت المسرح اسم الخطوة
  (`label`) بالبرتقالي `#f9bd29`.
- تحته الجملة كاملة بخط كبير، والكلمة الحالية (`token`) بخلفية برتقالية.
- نقاط تقدّم الخطوات، وأزرار: «إعادة»، و«الأحدث» مع «+N بانتظار» حين يوجد انتظار.
- قبل أي كلام: «سيظهر هنا كلام المحامي بالإشارة».
- سطر الحالة (حين يُمرَّر `status`): «يستمع للمحامي ●» مع النص الجزئي أثناء الكلام؛ إن توقف أو مُنع
  المايك أو كان المتصفح لا يدعم الاستماع ← رسالة واضحة وزر «تشغيل» (`onRetry`)، ولغير المدعوم:
  «استعمل Chrome أو Safari، أو اكتب بوضع المحامي».
- ألوان الهوية: لوحة `#0b1630`، أزرق `#136fb0`، برتقالي `#f9bd29`؛ RTL وخط Thmanyah.

## 7. أين تظهر

القاعدة: **الشاشة التي أمام الأصم تعرض المترجم الكبير.**

| الحالة | المترجم | مصدر الجمل |
|---|---|---|
| جلسة لابتوب بلا جوال | على اللابتوب | جمل المحامي من محادثة الجلسة (بعد مرشّح الصدى)، و`id` = `${at}:${text}` |
| لابتوب = المحامي، جوال = الشخص | على الجوال (`/join`) | عبارات المحامي القادمة من الغرفة |
| لابتوب = الشخص، جوال = المحامي | على اللابتوب | عبارات المحامي القادمة من الغرفة |

- **`SessionRoom.jsx`**: منطقة الكاميرا تنقسم على الشاشات الواسعة (≥ lg) إلى نصفين: المترجم والكاميرا؛
  وعلى الضيقة يصير المترجم بطاقة أعلى الكاميرا (حتى 45% من الارتفاع) قابلة للطي إلى شريط. وضع ملء
  الشاشة يشمل المترجم. سطر الحالة يأتي من العدسة عبر خاصية جديدة في `Home`:
  `onSpeechState({ state, partial, error, retry })`، حيث `state` واحدة من:
  `listening` (يستمع)، `off` (الاستماع مطفأ ← `retry` يشغّل `receiveEnabled`)، `error` (مايك مرفوض أو خطأ ←
  `retry` يعيد التشغيل)، `unsupported` (لا `SpeechRecognition` في المتصفح ولا Whisper من الخادم).
- **صندوق «اكتب وانطق»** بلا جوال: مفتاح «أنا: الشخص / المحامي» (الافتراضي الشخص).
  - الشخص: يُنطق ويُسجَّل كما الآن.
  - المحامي: يُسجَّل في المحادثة كمحامٍ ويذهب للمترجم، **ولا يُنطق**.
  - مع جوال مرتبط يختفي المفتاح ويبقى الدور ثابتاً كما الآن.
- **`JoinSession.jsx`** (جوال الشخص): ترويسة ← المترجم (`compact`، نحو 55% من الارتفاع) ← الكاميرا
  ← الردود السريعة. تُمرَّر `onConversation` إلى `Home` لالتقاط عبارات المحامي.
- `Home` يأخذ خاصية `hideSignCoach`؛ المنصة تمررها فيختفي المربع الصغير. العدسة الحرة (`/app/lens`)
  لا تمررها فيبقى المربع كما هو.

## 8. الأخطاء
- فيديو لا يُحمَّل ← تظهر الكلمة مكتوبة وتمضي اللوحة بعد 4000ms على الأكثر؛ لا توقف.
- المتصفح لا يدعم التعرّف الصوتي، أو المايك مرفوض ← سطر الحالة (القسم 6)؛ الكتابة بوضع المحامي تعمل دائماً.
- جملة من حروف ربط فقط ← لا خطوات، تُعرض كنص فقط في المحادثة ولا تدخل الطابور.
- انقطاع الغرفة مع جوال مرتبط ← سلوك الربط الحالي دون تغيير.

## 9. الاختبار
- **Vitest**:
  - `signTranslate.test.js`: جملة سيناريو كاملة ومحتواة؛ كلمة معروفة بسوابق ولواحق (`والأوراق`،
    `قضيتك`، `محاميك`)؛ عبارة من كلمتين (`من فضلك`)؛ حروف الربط تُتخطّى؛ تهجئة ≤ 4 حروف مع `لا`؛
    بطاقة للأطول وللأرقام؛ `token` يشير للكلمة الصحيحة؛ نص فارغ.
  - `signQueue.test.js`: الترتيب، عدم القطع، تجاهل id مكرر، `pending`، القفز عند تجاوز 3، `replay`.
  - `speechBuffer.test.js` (مؤقتات وهمية): مقاطع متتالية تخرج جملة واحدة بعد السكون؛ لا تكرار.
- **في المتصفح** (`npm run dev`):
  - جلسة بلا جوال: الكتابة بوضع المحامي تُشغّل المترجم؛ ثلاث جمل متتالية تُعرض بالترتيب و«+N بانتظار».
  - نافذتان عبر QR: ما يكتبه اللابتوب كمحامٍ يظهر في مترجم الجوال.
- **على جهاز المستخدم**: المايك الحقيقي (لا يعمل داخل متصفح المعاينة).

## 10. قيود عامة
- React 19 + Vite + Tailwind 4 الحالية، **بلا مكتبات جديدة**.
- يعمل بلا خادم وبلا إنترنت عدا التعرّف الصوتي للمتصفح (Whisper من الخادم اختياري كما الآن).
- العربية فقط، RTL، هوية «المحامون العرب».
- اختبارات الويب الحالية (66) تبقى خضراء.
